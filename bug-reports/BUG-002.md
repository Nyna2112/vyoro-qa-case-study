## Requirement analysis
Progress of the project depends on status of the application, based on the status the progress will change. Example: if the status of the application is pending, then the progress should show 0% because the user has not been accepted for that project yet.

## Test planning
I'm going to test whether the status change of the application reflects the progress or not by exploratory, manual, black box, functional, sanity testing, integration testing, re-testing because the progress should not be 100% when the status is still pending.

## Scenario
Does status change reflect the progress of the project or not – student portal

## Steps to reproduce
1. Go to the student portal
2. Login via a student account
3. Go to projects page and apply for an open project
4. Go to track applications page
5. Click on the applied project
6. Check the status of the project – whether it's pending or accepted
7. If it's pending, check the progress bar of the project – is it 0 or 100%

## Expected result
If it's pending, the progress bar should show 0%.

## Actual result
The progress bar is showing 100% even though the status is pending (that means the student is not yet accepted for that project).

## Severity and priority
- Severity: Medium (as it doesn't stop student from submitting the project)
- Priority: Medium or Low because it only causes ui mismatch but doesn't stop the user from doing the project and submitting it

## Test execution
Found the bug while re-testing the status feature and while implementing the progress bar feature for the first time in the portal.

## Test closure
- Reported the bug to the developer via whatsapp
- Retested whether it's working fine or not after fixed
- Checked the status of the bug and changed it to done once it's fixed
